    معنى الأخطاء الشائعة وحلها
    • SenderIdMismatch: المفتاح من مشروع Firebase غير المشروع اللي المتصفحات اشتركت فيه ({{ web_project }}). نزّل المفتاح من نفس المشروع.
    • ThirdPartyAuthError أو token-subscribe-failed: مفتاح Web Push (VAPID) في الموقع مش من نفس المشروع. من Firebase ← Project settings ← Cloud Messaging ← Web Push certificates انسخ المفتاح وابعتهولي.
    • PERMISSION_DENIED أو «Firebase Cloud Messaging API has not been used»: فعّل Firebase Cloud Messaging API في Google Cloud للمشروع.
    • permission-blocked أو NotAllowedError: الإذن مرفوض في المتصفح. اضغط على القفل جنب الرابط ← الإشعارات ← سماح.
    • unsupported-browser: المتصفح مش بيدعم الإشعارات. على الآيفون لازم تضيف الموقع للشاشة الرئيسية الأول (iOS 16.4+).
    • Firebase قال «نجح» ومفيش إشعار ظهر: إشعارات المتصفح مقفولة من إعدادات الجهاز (في ويندوز: Settings ← Notifications، وتأكد إن Focus Assist/Do not disturb مقفول)، أو المتصفح مقفول خالص.

    إمتى بيتبعت إشعار تلقائي؟

    • مقال جديد: أول ما يتحفظ بحالة «منشور» (أو يتحول من مسودة لمنشور).
    • سؤال جديد: لما يكون معتمد وليه إجابة رسمية. لو اعتمدته من غير إجابة، الإشعار بيستنى لحد ما تضيف الإجابة (من نفس صفحة السؤال).
    • سؤال زائر جديد محتاج مراجعة: إشعار للأدمن بس.
    • محتوى كتير مرة واحدة (زي دفعات المقالات اللي بتتضاف مع التحديثات): إشعار واحد مجمّع بدل عشرات الإشعارات.
    • وتقدر تبعت يدويًا من قائمة المقالات أو الأسئلة: حدد ← «🔔 إرسال إشعار للزوار الآن».
